インシデント番号: INC0010001
sys_id: 9ee470b483d4d310c97095d0deaad394

## 障害概要
お天気アプリ（server.js）の `GET /api/weather` 呼び出しで、エラーコード **GEOCODING_TIMEOUT** を返し、クライアントに「位置情報サービスへの接続がタイムアウトしました」と表示される。HTTP ステータスは **504**。インシデント記載より、郵便番号→住所変換（zipcloud）は成功している一方で、住所→緯度経度変換（Open-Meteo Geocoding API）へのリクエストがアプリ側のタイムアウト（TIMEOUT_MS=10000）を超過し、axios の `ECONNABORTED` 相当のタイムアウトに至っている状況。

## 障害カテゴリ
ネットワーク障害（外部 API への接続タイムアウト）

## 参照したナレッジ
- 「GEOCODING_TIMEOUT」：発生条件、根本原因パターン、確認手順、再発防止策
- 外部依存サービス一覧（Open-Meteo Geocoding のタイムアウト 10 秒）

## 根本原因仮説
- 仮説1: Open-Meteo Geocoding 側の障害/高負荷により応答が 10 秒以内に返らずタイムアウトした
  - 根拠: ナレッジの GEOCODING_TIMEOUT の根本原因パターンに「Open-Meteo サービス障害」を明記。インシデントでも zipcloud 成功・geocoding 失敗と切り分けができている。
- 仮説2: アプリ〜Open-Meteo 間のネットワーク経路（DNS/遅延/輻輳等）により応答遅延が発生した
  - 根拠: ナレッジの根本原因パターンに「ネットワーク経路の遅延」を明記。インシデントの症状が「接続がタイムアウト」であり、典型的な外部接続遅延/到達性問題のパターン。
- 仮説3: フォールバック検索パターンの多重実行により、アプリ側処理が遅延しタイムアウトとして観測されている
  - 根拠: ナレッジに「フォールバック検索パターンの多重実行による遅延」「最大5パターン × 10秒 = 最大50秒の可能性」を明記。実装次第で、呼び出し方が逐次/並列・タイムアウト設定の置き方によって、タイムアウトの発生頻度が上がり得る。

## 確認手順
1. アプリ稼働環境から Open-Meteo Geocoding への疎通確認（ナレッジ手順）
   - `curl "https://geocoding-api.open-meteo.com/v1/search?name=Tokyo&count=1"`
2. Open-Meteo ステータスページ確認（ナレッジ手順）
   - https://status.open-meteo.com
3. アプリログ確認
   - `GEOCODING_TIMEOUT` の発生時刻、対象リクエスト、axios エラー（`ECONNABORTED` 等）、リクエスト先 URL を特定
4. フォールバック検索パターン数と実行方式の確認（ナレッジ手順）
   - 最大何パターン試行しているか、各試行のタイムアウト値、逐次実行になっていないか（合算で遅延が増えていないか）

## 影響範囲
- 影響機能: `GET /api/weather`（郵便番号から天気取得）で、住所→緯度経度変換が必要なケース
- 影響ユーザー: Open-Meteo Geocoding への応答が 10 秒を超えるタイミングで利用したユーザー
- 影響範囲の切り分け: zipcloud が成功しているため、郵便番号→住所変換機能は影響軽微/なし（当該事象に限る）

## 暫定対処案
- タイムアウト発生時のリトライ（回数・間隔を制限）を導入、または運用で一時的に再試行を案内
- Open-Meteo のステータス異常時は、エラーメッセージを「外部サービス障害の可能性」へ寄せ、ユーザーに再試行を促す
- フォールバックを複数試行している場合、暫定的に試行回数を減らす/最も成功率の高いパターンに絞る

## 再発防止策
- 短期対策:
  - フォールバックパターンごとのタイムアウトを短縮（例：3秒）し、全体の待ち時間上限を制御（ナレッジ記載）
  - タイムアウト時の限定的リトライ（指数バックオフ等）を実装
- 中期対策:
  - Geocoding 結果のキャッシュを実装（同一郵便番号/住所の再問い合わせ削減：ナレッジ記載）
  - 監視: GEOCODING_TIMEOUT（504）の発生率、外部 API レイテンシ、DNS 失敗率をメトリクス化しアラート設定
- 長期対策:
  - 代替の緯度経度取得手段（別プロバイダ/API）を追加し、Open-Meteo 障害時にフォールバックできる設計にする
